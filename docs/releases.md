# Подпись и GitHub Releases

## Что уже настроено

- `Android CI` собирает устанавливаемый **debug APK**, запускает JVM-тесты и lint, сохраняет APK и отчёты в Artifacts.
- `Android Release` запускается по тегу `v1.0.0` или `v1.1.0-beta.1`, выполняет тесты, release lint и сборку **подписанного release APK**.
- Перед публикацией APK проверяется `apksigner verify`. Публикуются `KNITUshka-v1.0.0.apk` и SHA-256, release notes формируются GitHub автоматически.
- Теги с суффиксом, например `-beta.1`, создают prerelease.
- Без секретов workflow завершится ошибкой **до создания релиза**. Автоматической подмены на debug APK нет.

Публичный релиз при подготовке репозитория намеренно не создаётся.

## Один раз: ключ и GitHub Secrets

В существующем проекте release-подписи не было. Создай отдельный ключ релизов **вне репозитория**, сохрани его резервную копию и пароли в надёжном месте. Не используй локальный debug keystore как публичный ключ релизов.

Пример интерактивного создания ключа; пароли вводятся по запросу и не попадают в историю команд:

```bash
keytool -genkeypair -v -storetype JKS \
  -keystore "$HOME/knitushka-release.jks" \
  -alias knitushka -keyalg RSA -keysize 3072 -validity 10000
```

В репозитории GitHub открой **Settings → Secrets and variables → Actions → New repository secret** и добавь:

| Secret | Значение |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | Keystore, закодированный в Base64 без переносов строк |
| `ANDROID_KEYSTORE_PASSWORD` | Пароль хранилища |
| `ANDROID_KEY_ALIAS` | Алиас ключа, например `knitushka` |
| `ANDROID_KEY_PASSWORD` | Пароль ключа |

Base64 — кодирование, **не шифрование**. Передавай значение непосредственно в интерфейс Secrets или через безопасный менеджер секретов; не коммить его, не добавляй в issue и не публикуй в логе CI. Например, закодировать файл в отдельный приватный временный файл можно так:

```bash
umask 077
base64 < "$HOME/knitushka-release.jks" | tr -d '\n' > "$HOME/knitushka-release.base64"
```

После настройки удали временный Base64-файл. Исходный keystore и резервную копию сохрани вне Git. Для обновлений приложения всегда нужен тот же ключ; его утрата может сделать обновление существующей установки невозможным.

## Выпуск версии

1. Убедись, что `main` прошла Android CI и версия протестирована на устройстве.
2. В `android/app/build.gradle.kts` **увеличь `versionCode`** относительно предыдущего опубликованного APK и закоммить изменение. Сейчас исходное значение — `1`. `versionName` при релизе будет взят из тега без `v`; локальное значение по умолчанию сохранено.
3. Отправь обычный коммит и тег:

```bash
git switch main
git pull --ff-only
git tag -a v1.0.0 -m 'Android v1.0.0'
git push origin main
git push origin v1.0.0
```

4. Открой **Actions → Android Release**. После успешной проверки подписи workflow создаст Release и загрузит APK с контрольной суммой.

Не переиспользуй опубликованные теги и не применяй force push. Если версия уже опубликована, исправление выпускается новым тегом и с большим `versionCode`.

## Локальная подписанная сборка

Gradle читает только переменные окружения:

- `ANDROID_KEYSTORE_PATH` — абсолютный путь к keystore вне репозитория;
- `ANDROID_KEYSTORE_PASSWORD`;
- `ANDROID_KEY_ALIAS`;
- `ANDROID_KEY_PASSWORD`.

Задай их в приватном окружении, затем из `android/` выполни:

```bash
./gradlew :app:testDebugUnitTest :app:lintRelease :app:assembleRelease \
  -PandroidVersionName=1.0.0 --no-configuration-cache
```

Все четыре переменные должны быть заданы вместе. Без них локальный `assembleRelease` сохраняет прежнее поведение Gradle и может собрать **unsigned APK** — такой файл нельзя выдавать за готовую установку. Workflow релизов этот сценарий блокирует. Не запускай релизную сборку с секретами на недоверенном коде.

## Разрешения и безопасность CI

В workflow релизов job имеет `contents: write` для встроенного `GITHUB_TOKEN`; личный access token не нужен. CI pull requests имеет только `contents: read` и не использует секреты подписи. Файл keystore восстанавливается в `RUNNER_TEMP`, а не внутри checkout, и удаляется шагом `always()`; configuration cache для подписанной сборки отключён.

Оставь включёнными GitHub Actions для репозитория и разреши используемые actions, если в аккаунте настроены ограничения. Рекомендуется защитить `main` и теги `v*` от случайной публикации. Пока iOS готовится отдельно, теги `v*` относятся к Android.

CI debug APK подписан временным debug-ключом runner. Его подпись может отличаться между сборками; он не предназначен для стабильного канала обновлений. При переходе с уже установленной debug-версии на release подпись также меняется. Не удаляй старую установку, не приняв возможную потерю локального кэша и настроек.
