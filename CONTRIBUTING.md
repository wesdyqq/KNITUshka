# Участие в разработке

Спасибо за помощь КНИТУшке! Для небольших исправлений можно сразу открыть pull request; заметное изменение поведения лучше сначала обсудить в Issues.

## Запуск Android-проекта

Инструкция по окружению: [docs/getting-started.md](docs/getting-started.md).
Открывай `android/` в Android Studio, сохраняя общие документы и `.github/` в корне репозитория.

```bash
git switch -c fix/short-description
cd android
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Перед PR проверь:

- Проект собирается, доступные JVM-тесты проходят; новые случаи парсинга покрыты фикстурами и тестами.
- Не изменились `applicationId`, `namespace` и совместимость с сохранёнными данными без отдельного обсуждения.
- Сохранённое расписание не теряется при ошибке сети или изменении сайта.
- Жесты имеют альтернативу в виде кнопок; проверены перенос длинных названий, крупный шрифт и обе темы.
- В diff нет `.idea/`, `local.properties`, APK, кешей, keystore, паролей и другой локальной информации.

## Pull request

Опиши задачу, изменения и выполненные проверки. Для изменений интерфейса приложи настоящие скриншоты, не содержащие личных данных. Отметь проверки, которые не удалось выполнить, вместо утверждения, что всё протестировано.

Старайся сохранять принятый стиль Kotlin и Compose и не добавлять зависимости без необходимости. Изменения только документации или `ios/` не должны требовать Android-сборки.

## Ошибки и предложения

В баг-репорте укажи версию приложения, Android и модель устройства, шаги воспроизведения и ожидаемый результат. Для ошибок расписания полезны дата, группа и ссылка на страницу источника. Удали из логов токены, идентификаторы устройства и личные данные.

## Лицензия и безопасность

Отправляя вклад, ты соглашаешься распространять его на условиях [MIT](LICENSE) и подтверждаешь право публиковать эти материалы. Не добавляй чужие изображения и данные без необходимых прав.

Секреты подписи хранятся только локально вне Git или в GitHub Actions Secrets. Выпуск выполняет [Android Release](.github/workflows/android-release.yml). О подозрении на утечку ключа не сообщай вместе с самим ключом в публичном issue.
